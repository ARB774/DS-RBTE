# Описания классов задач среды TOCPEOPLE

**Рабочий продукт:** WP-45

**Статус:** черновик; шесть описаний рассмотрены пилотом

**Формат:** проектное представление `TaskSignature@Context` по FPF C.22

Документ фиксирует признаки задач, влияющие на последующий выбор способов работы. Он не выбирает метод и не устанавливает функции программной платформы. Значение «неизвестно» сохраняется, если характеристика важна, но ещё не определена для конкретной ситуации.

## 1. Провести трансформацию, начав без мандата

**Вопрос применения:** какие способы работы подходят инициатору, который должен получить мандат, а затем провести трансформацию организации?

### Предмет задачи

- Роль: инициатор трансформации.
- Целевая деятельность: провести трансформацию, начав без формального мандата.
- Объект изменений: управленческие решения, правила, показатели, роли и распределение ресурсов организации.
- Граница: от распознавания системного разрыва до получения мандата, проведения и закрепления трансформации.
- Итог: изменившиеся решения и результаты организации, а не только согласие первого лица.

### Значимые характеристики

| Характеристика | Текущее значение |
|---|---|
| Формальный мандат в начале | нет |
| Необходимость получить мандат | да |
| Доступ к первому лицу | неизвестно |
| Готовность первого лица обсуждать проблему | неизвестно |
| Обоснованность предлагаемого решения | неизвестно |
| Полномочия инициатора | ограничены собственной функцией |
| Охват изменений | выходит за границы функции инициатора |
| Союзники и сотрудничество команды | неизвестно |
| Риск для положения инициатора | присутствует, величина неизвестна |
| Доступ к фактам и возможность рабочей пробы | неизвестно |
| Необходимость закрепить изменения | да |

### Ограничения и результат

Инициатор не может присвоить полномочия первого лица; согласие без полномочий и ресурсов не считается мандатом; работа не должна создавать недопустимый риск. Результат достигнут, когда первое лицо предоставило явный мандат, а инициатор использовал его для проведения и закрепления трансформации.

## 2. Научиться управлять существующим бизнесом до создания нового

**Вопрос применения:** какие способы работы подходят собственнику, который хочет создать новое направление, но ещё не обеспечивает устойчивое управление существующим бизнесом?

### Предмет задачи

- Роль: собственник действующего бизнеса.
- Целевая деятельность: научиться понимать существующий бизнес и управлять им.
- Объект изменений: существующая система управления и решения собственника.
- Граница: от неудовлетворительных результатов до устойчивой работы бизнеса без постоянного вмешательства собственника.
- Итог: собственник может направить ресурсы на новое направление, не воспроизводя прежние проблемы управления.

### Значимые характеристики

| Характеристика | Текущее значение |
|---|---|
| Существующий действующий бизнес | есть |
| Удовлетворённость его результатами | недостаточная |
| Понимание причин результатов | неизвестно |
| Зависимость решений от собственника | высокая или неизвестная |
| Потребность в постоянном контроле | присутствует |
| Новое направление | замысел или начальная работа |
| Ресурсы для двух направлений | ограничены |
| Способность команды управлять без собственника | неизвестно |
| Подтверждённое улучшение существующего бизнеса | отсутствует |
| Высвобождение времени собственника | не подтверждено |

### Ограничения и результат

Новое направление не должно служить бегством от проблем существующего бизнеса; делегирование само по себе не подтверждает снятие проблемы; существующий бизнес не обязан стать идеальным. Результат достигнут, когда собственник понимает причины результатов, добился проверяемого улучшения, создал работающий контур управления и высвободил ресурсы для нового направления.

## 3. Обеспечить предсказуемое завершение проектов

**Вопрос применения:** какие способы работы подходят руководителю проектного бизнеса, в котором проекты конкурируют за общие ресурсы и регулярно завершаются позже обещанного срока?

### Предмет задачи

- Роль: руководитель проектного бизнеса или портфеля проектов.
- Целевая деятельность: управлять выполнением нескольких проектов.
- Объект изменений: поток проектов и использование общих ресурсов.
- Граница: от запуска проекта до сдачи результата и оформления документов.
- Итог: проекты завершаются в обещанные сроки без регулярных простоев и пожарного перераспределения ресурсов.

### Значимые характеристики

| Характеристика | Текущее значение |
|---|---|
| Одновременно выполняемые проекты | больше одного |
| Общие ресурсы | бригады, снабжение, транспорт, материалы, внимание руководителя |
| Доля проектов с увеличенным сроком | около 50% |
| Простои | присутствуют, величина неизвестна |
| Квалифицированные работники | не всегда доступны вовремя |
| Срочные закупки и остатки материалов | присутствуют и растут |
| Документы и акты | часть оформляется поздно |
| Правила приоритетов | неизвестно |
| Доступность фактического состояния проектов | частичная |
| Возможность провести пилот | есть |

### Ограничения и результат

Нельзя остановить текущую работу ради исследования; локальная занятость людей не подтверждает улучшение потока; сокращение запасов не должно вызывать остановку работ. Результат проверяется по завершению проектов в обещанные сроки, сокращению простоев и срочных перераспределений без роста избыточных остатков. Для проверки нужны сопоставимые сведения до и после изменения, но способ их получения и обработки пока не определён.

## 4. Распространить новый способ мышления среди управленцев

**Вопрос применения:** какие способы работы подходят собственнику, который хочет, чтобы большинство управленцев регулярно пересматривало предположения, лежащие в основе решений?

### Предмет задачи

- Роль: собственник или первое лицо.
- Целевая деятельность: создать распределённую способность управленцев пересматривать исходные предположения.
- Объект изменений: воспроизводимый способ принятия управленческих решений.
- Граница: большинство управленцев компании и их реальные рабочие решения.
- Итог: пересмотр предположений происходит без постоянного запуска со стороны собственника.

### Значимые характеристики

| Характеристика | Текущее значение |
|---|---|
| Полномочия первого лица | есть |
| Предшествующая трансформация | есть |
| Опыт совместного пересмотра предположений | есть у части команды |
| Зависимость от собственника и внешнего партнёра | присутствует |
| Реальные ситуации для практики | есть |
| Общая цель, доверие и безопасность | требуется проверить |
| Возможность признавать ошибки без санкций | требуется проверить |
| Изменение решений и закрепление в правилах | требуется проверить |
| Регулярность пересмотра | недостаточная или неизвестная |

### Ограничения и результат

Нельзя изменить мышление управленца вместо него; участие, знание метода и число обсуждений не подтверждают результат; принуждение к откровенности создаёт риск. Результат достигнут, когда большинство управленцев выявляет и проверяет предположения, изменяет на этой основе решения и повторяет работу в новых ситуациях без постоянного вмешательства собственника.

## 5. Масштабировать трансформацию на предприятия холдинга

**Вопрос применения:** какие способы работы подходят центральному отделу производственной системы, который должен поддерживать самостоятельные трансформации нескольких предприятий холдинга?

### Предмет задачи

- Роль: руководитель центрального отдела производственной системы.
- Целевая деятельность: проводить и масштабировать трансформации предприятий холдинга.
- Объект изменений: системы управления отдельных предприятий.
- Граница: от определения проблемной ситуации предприятия до закрепления изменений его руководством.
- Итог: предприятия продолжают трансформацию без постоянного ручного управления со стороны центрального отдела.

### Значимые характеристики

| Характеристика | Текущее значение |
|---|---|
| Количество предприятий | несколько |
| Различие их ситуаций | существенное |
| Местное руководство | есть |
| Полномочия центра и местных руководителей | точные границы неизвестны |
| Заинтересованность местного руководства | различается или неизвестна |
| Согласованность целей | требуется проверить |
| Локальная оптимизация | присутствует |
| Способность видеть предприятие как систему | недостаточная или различается |
| Доступ центра к данным и людям | различается |
| Одновременные трансформации | больше одной |
| Зависимость от центрального специалиста | высокая или неизвестная |

### Ограничения и результат

Центр не может управлять предприятиями вместо местных руководителей; предприятия нельзя считать одинаковыми; единый набор мероприятий не гарантирует одинакового результата. Результат достигнут, когда местные руководители определяют собственную проблемную ситуацию, принимают ответственность, закрепляют изменения и продолжают трансформацию без постоянного участия центра.

## 6. Развиваться на материале недостаточно результативного консультационного проекта

**Вопрос применения:** какие способы работы подходят консультанту, которому необходимо исследовать собственный вклад в недостаточный результат проекта и изменить свой способ работы?

### Предмет задачи

- Роль: консультант по управлению.
- Целевая деятельность: учиться на результате собственного консультационного проекта.
- Объект изменений: предположения консультанта о клиенте, проблеме, своей экспертности и способе вмешательства.
- Граница: от обнаружения недостаточного результата до проверки изменённого способа работы в следующем взаимодействии.
- Итог: консультант изменил свой способ работы, а не только сформулировал объяснение неудачи.

### Значимые характеристики

| Характеристика | Текущее значение |
|---|---|
| Реальный консультационный проект | есть |
| Ожидаемый результат | заявлен, точность неизвестна |
| Фактический результат | недостаточный |
| Вклад клиента | частично известен |
| Вклад консультанта | не исследован |
| Объяснение неудачи | преимущественно клиент и обстоятельства |
| Реакция на критическую обратную связь | защитная или требуется проверить |
| Уверенность в экспертности | высокая |
| Доступность рассуждений для проверки | недостаточная |
| Готовность проверить собственные предположения | низкая или неизвестная |
| Возможность повторного взаимодействия | требуется определить |

### Ограничения и результат

Нельзя заранее считать консультанта причиной неудачи; критика личности не заменяет исследование рассуждений; признание ошибки без изменения действий не снимает проблему; проверка не должна создавать недопустимый риск клиенту. Результат достигнут, когда консультант исследовал собственный вклад, пересмотрел предположения, изменил способ работы и проверил его в следующем взаимодействии по заранее определённым признакам.
