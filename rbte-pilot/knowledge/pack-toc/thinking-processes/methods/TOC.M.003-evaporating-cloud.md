# Грозовая туча (Evaporating Cloud / EC)

> Инструмент для **Вопроса 2: На что менять?** (совместно с ДБР и NBR).

- **Логика:** necessity-based (чтобы → нужно)
- **Назначение:** сформулировать конфликт и найти инъекцию (решение)
- **Ключевой принцип:** вместо компромисса (B и C удовлетворяются частично) — прорывное решение, при котором B и C удовлетворяются одновременно (`TOC.D.005`).

## Структура

```
A (Общая цель)
  ├── B (Необходимое условие 1) ← D  (Метод 1: действия для достижения B)
  └── C (Необходимое условие 2) ← D' (Метод 2: действия для достижения C)
                                     D ↕ D' (конфликт)
```

Чтение: «Чтобы достичь A, нужно одновременно обеспечить B и C. Чтобы обеспечить B, необходимо делать D. Чтобы обеспечить C, необходимо делать D'. D и D' прямо конфликтуют.»

**Базовые посылки ТОС (зачем EC работает):**
1. У системы всегда есть общая цель → у любых её частей тоже есть общая цель
2. В системе не может быть конфликта между частями, поскольку есть общая цель
3. Следовательно: любой конфликт в системе может быть снят
4. Конфликты существуют только из-за ошибочных посылок

> `[АТБ]` Контекст формирует убеждения → убеждения формируют интересы/цели → личный выбор определяет поведение → поведение даёт результат. Менять поведение без смены убеждений бессмысленно. EC вскрывает убеждения, а не симптомы.

## 3 этапа работы с Тучей

```
Этап 1: ПОНИМАНИЕ ПРОБЛЕМЫ   → построить диаграмму A–B–C–D–D'
Этап 2: ВЫЯВЛЕНИЕ ПРЕДПОЛОЖЕНИЙ → найти убеждения за каждой стрелкой
Этап 3: НАХОЖДЕНИЕ РЕШЕНИЯ   → оспорить предположения → сформулировать инъекцию
```

**Этап 1. Построение диаграммы.** Последовательность вопросов: (1) Что является общей целью? → A; (2) Какие два необходимых условия для A? → B, C; (3) Что делать для B? → D; (4) Что делать для C? → D'; (5) В чём именно конфликт D и D'? Проверка: читать каждую стрелку «Чтобы… нужно…».

**Этап 2. Выявление исходных предположений (убеждений).** Для каждой стрелки: «Чтобы обеспечить [B], мы должны делать [D], **потому что...**». То, что за «потому что» — исходное предположение (опознание ИП — `TOC.M.004`).

Свойства хорошего предположения: поясняет именно связь (не повторяет B и D); объясняет, почему D — единственное действие для B; относится к обоим элементам стрелки; не содержит причинно-следственной связи внутри. Проверка: «Если хотим [B] И если [предположение], то должны [D]».

> `[АТБ]` Предположения за D–D' чаще отражают недостаток чего-либо (знаний, уверенности, признания) или существующие правила/показатели. Если трудно сформулировать: «Чего не хватает, из-за чего конфликт существует?»

**Этап 3. Оспаривание предположений и формулировка инъекции.** По каждому предположению: «А **действительно ли** [предположение]?». Часть предположений — непреложные истины (оставляем); часть — устарели или условны (помечаем ошибочными). Одного оспоренного предположения достаточно для снятия конфликта.

> `[АТБ]` Правильнее говорить не «истинное/ложное», а «полезное/ограничивающее»: одно убеждение работает в одной компании и ошибочно в другой.

**Инъекция (Injection) — прорывное решение** (`TOC.WP.006`): действия, которые (1) удовлетворяют B и C одновременно, (2) опровергают ошибочное предположение, (3) создают контекст, в котором ошибочное предположение не реализуется.

## Критерии качества формулировок блоков

| Блок | Требование |
|------|-----------|
| Все блоки | Побудительные или полные простые предложения |
| Все блоки | Без причинно-следственных слов внутри (нет «потому что», «из-за», «чтобы») |
| D и D' | Формулируются как действия — **в формулировке есть глагол** («держим», «загружаем», не «запас», «загрузка»); полностью противоположны (в конфликте) |
| D и D' | `[АТБ]` **Только реально выполняемые действия** — то, что делается сейчас (изъявит. наст.: «отливаем», «экономим», «вкладываем»); не «можно делать» и не «нужно делать» |
| B и C | Реальные потребности в позитивной формулировке — без слова «не» |

## Проверка логики связей (чтение стрелок вслух)

1. «Для того чтобы [A], я должен добиться [B]»
2. «Для того чтобы добиться [B], я должен сделать [D]»
3. «Для того чтобы [A], я должен добиться [C]»
4. «Для того чтобы добиться [C], я должен сделать [D']»
5. [D] и [D'] находятся в конфликте
6. [D] ставит под угрозу достижение [C]
7. [D'] ставит под угрозу достижение [B]

Если любой пункт звучит нелогично → переформулировать блоки, не предположения.

**Проверка инъекции:** «Если [Инъекция], то смогу достичь [B] и [C] без блокирующего конфликта, потому что…». Если одновременного достижения нет — инъекция слабая. Доп. тест: «Если бы инъекция имела место, чувствовал бы я себя лучше?»

## Типы конфликтов и варианты применения

- Symptomatic (симптоматический) — проявление; Systemic / core conflict — корневой; Day-to-day — операционный.
- **Варианты (отдельные карточки):** личная дилемма — `TOC.M.006`; конфликт сторон — `TOC.M.007`; туча тушения пожара (Lieutenant's cloud) — `TOC.M.008`; туча иммунитета к изменениям — `TOC.M.009`.

**Типы инъекций:** breakthrough (win-win, снимает предположение полностью); flying pig (кажется невозможной, но решает); primary (главная инъекция решения).
