# Исполнение наставника предложения ценности

Порядок контекста: постоянное ядро → карточка → источник метода через MCP →
один активный модуль → один ход. Процедуры выделены из ТЗ по диапазонам строк;
`mentor-module.ts` задаёт вход, выход, завершение, ограничения и возобновление.
Подэтапы S6.1–S6.3 разделены. Ядро, шаблон карточки и модуль показа Тучи читаются
полностью. Редакции: DS-RBTE 047806b и Pack-TOC из pack-toc-sources.json.

## MCP

`scripts/mentor-method-mcp.mjs` предоставляет read-only инструменты
`search_mentor_methods` и `get_mentor_method`. Клиент выполняет настоящий stdio
MCP-вызов на каждом ходе. Документы DS-RBTE читаются из GitHub, приватный
Pack-TOC — через Contents API с `GITHUB_READ_TOKEN` либо существующим
`PILOT_GITHUB_MCP_TOKEN` (первое имя имеет приоритет). Процесс
не получает сообщения участника, ключ модели или доступ к БД.

Полный текст после CRLF → LF сверяется по SHA-256 из
`lib/value-proposition-evidence.json`; хэш фрагмента также проверяет клиент.
Кэш имеет права 600 и разделён по uid службы. Источник получения github /
verified-cache, дата, редакция и диапазон сохраняются и видны в интерфейсе.
При отказе сети и отсутствии проверенного кэша ход останавливается. Снимок
не подставляется как будто он получен онлайн. Для обновления редакций:
`python scripts/build-mentor-evidence.py` из rbte-pilot.

## Карточка и переходы

Состояние версии 2 хранится в существующем JSON-поле evidence; старое значение
сохраняется в legacyEvidence. Миграций нет. Карточка хранит пункты допуска с
точными цитатами участника, черновик, подтверждённые продукты, пакет перехода
и последний вопрос. Источники текущего хода сохраняются в поле sources.

На S0 модель извлекает сведения участника, приложение проверяет цитаты и
определяет незакрытый пункт из пяти критериев. Прежний разрыв наставника не
является доказательством. Экспертная гипотеза и путь проверки допускают
исследовательский режим; доступ к секретам не означает разрешение передавать их.

Вопрос об источниках получает прямой ответ без оценки учебной попытки. Просьба
объяснить не меняет продукт или этап. Явно выбранный тип сообщения имеет
приоритет. Для других этапов критерий должен иметь точную цитату из прочитанного
источника; вымышленные ссылки отклоняются. Проверка происхождения не доказывает
правильность смыслового применения методики.

Продукт показывается целиком. Только подтверждение готовой версии закрывает
модуль, сохраняет пакет перехода и разрешает чтение следующего модуля. Само
«да» без готового продукта не разрешает переход. У незавершённого черновика
нет кнопки подтверждения. Старый диалог не обнуляется: S0 восстанавливается
по всем сообщениям участника, другой этап впервые получает доступную историю.
Затем контекст удерживается карточкой, а история служит проверке происхождения.
Сообщение участника сохраняется отдельной транзакцией до вызова модели. Карточка
и ответ наставника сохраняются атомарно; при сбое появляется уведомление SERVICE,
а этап и рабочий продукт не меняются. Повтор использует то же сообщение без
дублирования. Идентификатор отправки защищает от двойной отправки формы, черновик
хранится в sessionStorage вкладки до подтверждённого сохранения. Блокировка строки
и проверка времени изменения защищают от потерянного параллельного хода.

Короткие пределы отдельных текстовых полей модели сняты: содержимое не обрезается.
Остаются типы, структура, проверка источников и общий бюджет ответа (5200 токенов,
128000 символов). Ошибки ответа обрабатываются без аварийной страницы.

## Проверки и поставка

Тесты проверяют MCP-транспорт, целостность источников, старый зацикленный
сценарий, вопросы об источниках и терминах, сохранение допусков, запрет перехода
без продукта и пакет перехода. mentor-source-check.ts читает источники всех
этапов через MCP; mentor-live-check.ts проверяет синтетический диалог с настоящей
моделью без чтения или записи пользовательских данных БД.

При поставке необходимы scripts, knowledge, два JSON-манифеста в lib и
зависимости MCP-сервера. Конфигурация и БД сохраняются, миграций нет. Откат
возвращает прежний релиз, который игнорирует новую карточку; история совместима.
