ПРОФИЛИ
Личная дилемма: TOC.M.006 + TOCT.13. Порядок D, D′, C, B, A.
Конфликт сторон: TOC.M.007 + TOCT.14. Порядок D, D′, B, C, A.
Тушение пожара: TOC.M.008 + TOCT.15. Порядок B, D, D′, C, A.
Иммунитет: TOC.M.009 + TOCT.16. Порядок B, D′, D, C, A.

Отличие иммунитета от прежнего PDF-варианта: полная карта TOCT.16 содержит
желаемое действие D. Человек сам формулирует его на основе наблюдаемого D′.
Проверяются личная значимость цели, организационные препятствия и подтверждение
самим человеком защищаемой приверженности C. Карта не является диагнозом.

Схема изначально пустая. Пользователь вводит собственные ответы прямо в блоки.
В каждом профиле — свои подписи, вопросы, границы применения и самопроверки.
Семь связей проверяются отдельно; исходные посылки и инъекции не подставляются
вместо пользователя. Для пожаров разделены срочное реагирование и разбор
механизма повторения; отдельно рассматриваются знания, полномочия, уверенность.

На каждом шаге можно раскрыть основания Pack-TOC и перейти к документам.
Отчёт проверки содержит ID источников. История и отпечаток проверки сохраняют
версию методики. После перехода со старой версии записи не удаляются, но
проверки потребуют пересмотра. Для иммунитета нужно самостоятельно дополнить D.

ОГРАНИЧЕНИЯ
Локально проверяются заполнение, явные повторы, причинные связки внутри блоков
и ответы самопроверки. Достоверность, смысл и логическая необходимость не
устанавливаются простой эвристикой. Нет обязательного количества убеждений
или повторов пробы. Некоторые документы Pack имеют статус draft. Не заявлены
сертификация DPF, корневой характер конфликта или доказанное освоение.

При наличии настроенного ключа OpenAI и отдельного согласия пользователя
сервер читает выдержки из включённых документов, сверяет их SHA256 и передаёт
их с контекстом текущего и предыдущих шагов. Ответ должен ссылаться только
на предоставленные источники. Полный закрытый репозиторий не отправляется.
На работающем сервере ключ ранее отсутствовал; этот пакет его не создаёт.
Без ключа остаются вопросы, самопроверки и локальные проверки по Pack-TOC.

ПРОВЕРКА И ЗАПУСК
npm ci
npm run lint
npm test
npm run build
npm start
Нужны существующие DATABASE_URL и параметры SSO-портала. Новых миграций БД нет.
Установщик делает резервную копию, собирает отдельный релиз и проверяет
четыре профиля на серверной БД с откатом проверочных данных до переключения.
Если проверка после переключения не проходит, возвращается предыдущий релиз.
Секреты и действующая конфигурация сервиса не перезаписываются.
